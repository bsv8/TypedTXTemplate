# 核心层 —— 字段编码

规范条款。帧类型 schema 可用的字段类型，以及每种类型的规范编码。

## 1. 适用于所有类型的规则

1. **定宽整数就是定宽。** 声明为 `u32` 的字段**必须**恰好给定 4 字节，解析时**必须**恰好消耗 4 字节。
   3 字节或 5 字节的字段是解析失败，不是需要被截断或钳位的值。
2. **整数是无符号小端的**，除非类型名另有说明。`u32le` / `u64le` 是规范写法；
   本规范中名为 `u32` 的类型也定义为小端，这样 Go 与 TypeScript 的实现不会有歧义。
   比特币的线格式和 *sighash* 前像都是大端 —— 那是另一回事，永远不会作为字段出现。
3. **字节数组是不透明的。** `bytes` 类型的字段就是它携带的那些字节。实现**禁止**重编码、规范化或解释它们。
4. **长度属于 schema，不属于取值。** 字段的字节长度已经由压栈划定。只有字段*内部*才需要长度前缀。
5. **任何字段禁止超过 520 字节**，任何帧的总长也**禁止**超过 520 字节
   （[encoding.md §4](encoding.md#4-共识限制)）。

## 2. 类型

| 类型 | 宽度 | 编码 |
|---|---|---|
| `u8` | 1 | 无符号整数 |
| `u32le` | 4 | 无符号，4 字节，小端 |
| `u64le` | 8 | 无符号，8 字节，小端 |
| `hash256` | 32 | 不透明摘要；字节序由生产者决定，**必须**原样保留 |
| `pubkey` | 33 | 压缩 secp256k1 点：`0x02`/`0x03` 前缀 + 32 字节大端 `x` |
| `sig64` | 64 | secp256k1 紧凑签名：`r` ‖ `s`，各 32 字节大端 |
| `bytes` | 0–520 | 不透明字节串；**在 schema 中定长**，或用下面的 `varlen` |
| `utf8` | 0–520 | **严格** UTF-8，不规范化、不加 BOM、不裁剪 |

### 2.1 `sig64` 与 DER

使用**紧凑** 64 字节形式（`r` ‖ `s`）。DER 形式大 8 字节，更重要的是它**不是规范的**：
同一个签名有多个合法 DER 编码，因此两个实现可能为同一个数学签名产出不同字节。
紧凑形式是唯一的。

实现**必须**拒绝 `s` 不落在曲线阶下半区的 `sig64`（可延展的 `s`），并且**必须**拒绝 `s` 为零。
验证时，高 `s` 签名是**无效**，而不是一个可以被规范化的签名。

### 2.2 `hash256` 与字节序

比特币在界面上按大端显示哈希，但内部计算与序列化用小端。`hash256` 字段**必须**被当作一个
采用**唯一约定字节序**的不透明 32 字节串，该约定由测试向量固定。
**提示：** 优先原样携带生产函数返回的字节，并在定义它的应用协议里记录该字节序。
**不要**做转换。

### 2.3 `utf8`

严格 UTF-8。实现**必须**拒绝不是合法 UTF-8 的 `utf8` 字段，**而不是**用替换字符修补 ——
静默修复载荷会摧毁本核心赖以存在的不可篡改保证。

## 3. `varlen`（应用协议扩展）

当长度不固定时，应用协议**可以**把字段声明为 `varlen`。编码是**首字节 + 该长度的数据**：

```
0x00–0xfb : 长度就在这个字节里，随后是这么多数据字节
0xfc      : 后面跟 2 字节小端长度，随后是这么多数据字节
0xfd      : 后面跟 4 字节小端长度，随后是这么多数据字节
```

一个 `varlen` 字段的长度开销最少 1 字节、最多 5 字节，所以**只要范围已知就应当用定宽**。
`bbs` 的 `v1-post` 正是出于这个原因刻意全部使用定宽。

## 4. 规范消息的组装

有些字段类型只有组合起来才有意义 —— 签名是对一条*消息*产生的，不是对一个字段产生的。
当应用协议定义这样一条消息时，它**必须**精确规定组装方式：就是一次字节拼接，
除了域分离前缀之外不再自带任何框架。有两条规则保证结果可复现：

- **顺序即 schema 顺序。** 字段按 schema 声明顺序拼接；未纳入消息的字段**必须**显式列出，
  而不是被静默省略。
- **域分离前缀是强制的。** 前缀为 ASCII，以 `|` 结尾，标明应用协议、版本与角色。
  参考实现在签名前先对组装好的消息做 `SHA256d`，因此无论其中有多少可变部分，
  被签名的长度始终是 32 字节。

`bbs` 的 `v1-post` 定义了三个前缀，见
[subprotocols/bbs/v1-post.md](../subprotocols/bbs/v1-post.md#41-签名)。

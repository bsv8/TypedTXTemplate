# 核心层 —— 注册表

规范条款。标签命名空间、注册表结构，以及已分配的标签。

## 1. 标签语法

```
BSV8:<TYPE>:<MAJOR>.<MINOR>
```

| 部分 | 规则 |
|---|---|
| `BSV8` | 命名空间。固定前缀，大写。其他任何命名空间都属于另一份规范。|
| `<TYPE>` | 大写 ASCII，`A`–`Z`、`0`–`9`、`_`。3–16 字节。|
| `:` | 字面分隔符 |
| `<MAJOR>.<MINOR>` | 十进制。不兼容变更时提升。|

示例：`BSV8:POST:1.0`、`BSV8:NODE:1.0`。

**版本的语义。** 解析器**必须**接受同一主版本下它认识的标签，**必须**拒绝不同主版本。
次版本提升**只允许**追加一个可选的末尾字段 —— 而由于不变量 I1 固定了字段数，
次版本提升实际上**不能**改变 schema。因此：

> **提示：** 在本核心中，次版本先留着不动，任何 schema 变更一律走主版本。

## 2. 注册表条目

注册表条目是规范条款，由以下属性组成：

| 属性 | 含义 |
|---|---|
| `tag` | 如上 |
| `fields` | 有序的 `(名称, 类型)` 列表 —— 见 [field-encodings.md](field-encodings.md) |
| `documented purpose` | 说明文字；非规范 |
| `frame limit` | 该类型的最大脚本长度；默认 520 |

实现**必须**携带它所声明支持的条目，并且**必须**拒绝任何不在其注册表中的标签
（[framing.md §3](framing.md#3-解析)）。

## 3. 申请标签

新标签在应用协议中申请，而不在核心层。流程是：

1. 选一个尚未分配的 `TYPE`。
2. 在 [`subprotocols/`](../subprotocols/README.md) 下的应用协议文档中发布 schema。
3. 把条目加入下面的表格，并加入共享测试向量（[conformance/](../conformance/README.md)）。

占用 `BSV8` 命名空间意味着承担 `bsv8` 项目的责任。**不要**为你并不维护的规范占用本命名空间的标签。

## 4. 已分配标签

| 标签 | 帧 | 字段 | 所有者 | 规范 |
|---|---|---|---|---|
| `BSV8:POST:1.0` | 论坛帖子或回复 | `version, boardId, postHash, parentHash, posterPub, fee, notAfterHeight, operatorSig, body` | `posterPub` | [bbs/v1-post.md](../subprotocols/bbs/v1-post.md) |

**价格不通过链上公告帧发现。** 报价由运营方经 `bsv8/ChannelProtocol` 的
`bsv8.bbs.quote.v1` 直接发给请求者，报价的**结果**（`fee`、`notAfterHeight`）被
`operatorSig` 锁定在帖子里。因此**不需要**一个"价格公告"帧 ——
`operatorSig` 覆盖 `fee`，价格已经不可篡改；再单独公告一次只会引入第二个可被链下修改的数字。
见 [bbs/v1-lifecycle.md §2](../subprotocols/bbs/v1-lifecycle.md#2-询价在范围外)。

## 5. 注册表的纪律

**注册表不是"值得关心的帧"的白名单。** 它唯一的职责是说明**怎么读一个帧**。由此得到两个
容易搞错的结论：

- 标签已注册、但本地实现对其无用的帧，仍然是合法的帧。解析器**禁止**基于语义原因
  静默丢弃已注册的未知类型；**可以**把它们透传。
- 标签**未**注册并不是链上的错误。它只是"本规范不解释这个脚本"。解析器**必须**返回"不是帧"，
  并继续扫描该交易的其他输出。

**注册不等于对数据的所有权主张。** 注册 `BSV8:POST:1.0` 说的是"怎么解码一个论坛帖"。
它没有说谁可以发帖、什么算合法板块、某个运营方有权收多少。那些是应用协议的规则，
而应用协议的*商业*规则完全在本规范之外。
